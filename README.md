# Quant Harbor 机器交易平台

Quant Harbor 是一个自托管的量化交易平台。它把交易所账户、策略设计、历史回测、模拟交易、资金分配和订单记录集中到一个中文 Web 界面中。

平台通过交易所 API 操作用户自己的账户，资金仍保留在交易所。API Key 会加密后存入本地数据库，不需要把资金转入平台。

## 已实现的功能

- 支持 Binance、OKX、Bybit 和 Kraken。
- 添加测试网或实盘 API 账户，并测试连接状态。
- 加密保存 API Key、Secret 和 Passphrase。
- 使用可视化向导创建策略，普通使用不需要写代码或 JSON。
- 支持 SMA、EMA、RSI、价格字段、条件组合、上穿和下穿等规则。
- 提供经典策略库，也可以保存自己的策略模板。
- 使用交易所历史 K 线进行回测，展示收益率、回撤、胜率和净值曲线。
- 支持模拟盘、交易所测试网和实盘执行。
- 设置每单投入、止损、止盈和手续费。
- 为不同策略分配不同资金比例。
- 支持一次性资金分配，以及带偏离容忍区间的动态比例校准。
- 后台持续检查策略信号，并保存订单与错误记录。
- 实盘交易默认锁定，必须通过服务器环境变量主动开启。

## 完整使用示例

下面创建一个 BTC/USDT 双均线模拟策略。假设模拟组合总资金为 10,000 USDT，希望只让这个策略使用其中 20%。

策略要求：

| 项目 | 设置 |
| --- | --- |
| 交易所 | Binance |
| 交易对 | BTC/USDT |
| 判断周期 | 1 小时 |
| 买入条件 | SMA 20 上穿 SMA 50 |
| 卖出条件 | SMA 20 下穿 SMA 50 |
| 组合总资金 | 10,000 USDT |
| 策略资金比例 | 20% |
| 策略初始资金 | 2,000 USDT |
| 每次最多投入 | 100 USDT |
| 止损 | 3% |
| 止盈 | 6% |
| 运行模式 | 模拟盘 |

### 第一步：选择策略模板

进入“策略库”，找到“经典双均线”，点击“放入策略向导”。程序会自动填入：

- 快线周期：20
- 慢线周期：50
- 买入：SMA 20 上穿 SMA 50
- 卖出：SMA 20 下穿 SMA 50

### 第二步：填写市场信息

在策略向导中填写：

- 策略名称：`BTC 一小时双均线`
- 交易所：`Binance`
- 交易对：`BTC/USDT`
- 判断周期：`1 小时`
- 运行模式：`模拟盘`

模拟盘不要求交易所 API 账户。测试网或实盘策略必须选择对应的交易所账户。

### 第三步：分配资金

选择“只在开始时按比例分配”，设置：

- 模拟组合总资金：`10000`
- 分配给这个策略：`20%`
- 每次最多投入：`100`

策略开始时会得到 2,000 USDT。以后如果它盈利到 2,400，这 2,400 会继续留在策略内；如果亏损到 1,800，也不会自动补回 2,000。

如果改成“每次开仓前动态校准比例”，程序会在下一次准备买入前，根据组合最新权益重新计算 20% 的目标资金。动态模式目前只允许在模拟盘使用。

### 第四步：设置风险

填写：

- 最大亏损：`3%`
- 目标盈利：`6%`
- 手续费：`10 bps`，即 0.1%

程序生成的中文说明类似：

> 程序将在 Binance 观察 BTC/USDT 的 1 小时行情。SMA 20 上穿 SMA 50 时买入，下穿时卖出。这个策略使用组合资金的 20%，只在开始时分配一次。

### 第五步：保存并回测

点击“保存并创建策略”，然后在策略卡片上点击“先回测”。回测结果会显示：

- 最终权益
- 总收益率
- 最大回撤
- 已平仓次数
- 胜率
- 净值曲线

收益率高并不代表策略可靠。还应检查最大回撤、交易次数、手续费影响，以及不同时间范围内是否都能保持相似表现。

### 第六步：启动模拟交易

回测结果符合预期后，点击“启动”。后台引擎会定期读取行情、计算信号并记录模拟订单。

建议顺序始终是：

```text
历史回测 → 模拟盘 → 交易所测试网 → 小额实盘
```

## 功能详细说明

### 1. 可视化总览

总览页面展示：

- 已连接的交易账户数量
- 已创建的策略数量
- 正在运行的策略数量
- 累计订单数量
- 各模拟策略的资金快照
- 策略运行比例
- 从策略想法到上线监控的量化流程

资金快照中的持仓暂时按入场价格估值，主要用于快速观察策略资金分布。

### 2. 交易所账户

账户页面可以添加 Binance、OKX、Bybit 或 Kraken API。

需要填写：

- 账户名称
- 交易所
- 测试网或实盘
- API Key
- API Secret
- Passphrase，部分交易所需要

保存后可以点击“测试连接”，平台会加载交易市场并读取账户余额，以验证域名、权限和凭据是否正常。

建议创建只具备现货交易权限的 API Key：

- 关闭提现权限。
- 设置交易所 IP 白名单。
- 测试网和实盘使用不同的 API Key。
- 不要把 API Key 写入源码、聊天记录或 README。

### 3. 可视化策略向导

策略向导分为四步：

1. 选择交易所、交易对、周期和运行模式。
2. 选择策略模板并填写指标参数。
3. 设置资金比例、每单投入和风险限制。
4. 阅读中文策略说明并保存。

当前提供四种可视化模板：

- SMA 双均线趋势
- EMA 双均线趋势
- RSI 超买超卖
- 价格与均线突破

程序会实时生成买入条件、卖出条件和完整中文说明。

### 4. 策略库

策略库内置以下经典例子：

| 策略 | 类型 | 默认规则 |
| --- | --- | --- |
| 经典双均线 | 趋势 | SMA 20/50 上穿买入、下穿卖出 |
| EMA 快速趋势 | 趋势 | EMA 12/26 上穿买入、下穿卖出 |
| RSI 超买超卖 | 震荡 | RSI(14) 低于 30 买入，高于 70 卖出 |
| 价格突破均线 | 突破 | 收盘价上穿 SMA50 买入，下穿卖出 |
| 趋势 + RSI 过滤 | 组合 | 双均线确认趋势，RSI 过滤过热信号 |

经典策略不能删除。点击“放入策略向导”可以套用并修改。

在策略向导最后点击“只保存到我的策略库”，可以保存自己的规则，但不会创建或启动交易策略。自定义模板可以重复套用，也可以删除。

### 5. 高级策略规则

普通用户不需要查看 JSON。需要组合复杂条件时，可以展开“高级模式”。

默认双均线规则：

```json
{
  "entry": {
    "all": [
      {
        "left": {"indicator": "sma", "period": 20},
        "op": "crosses_above",
        "right": {"indicator": "sma", "period": 50}
      }
    ]
  },
  "exit": {
    "any": [
      {
        "left": {"indicator": "sma", "period": 20},
        "op": "crosses_below",
        "right": {"indicator": "sma", "period": 50}
      }
    ]
  }
}
```

支持的操作数：

- 指标：`sma`、`ema`、`rsi`
- 行情字段：`open`、`high`、`low`、`close`、`volume`
- 常量：例如 `{"value": 30}`

支持的操作符：

- `>`、`<`、`>=`、`<=`
- `crosses_above`：上穿
- `crosses_below`：下穿

条件组合：

- `all`：所有条件都满足
- `any`：任意一个条件满足

平台只解释声明式规则，不会直接执行用户输入的 Python 代码。

### 6. 历史回测

回测会从所选交易所读取历史 OHLCV K 线，并按照策略规则模拟买卖。

回测考虑：

- 初始资金
- 单笔投入
- 手续费
- 止损
- 止盈
- 持仓变化

当前回测模型使用 K 线收盘价进行信号判断和模拟成交。它还没有包含订单簿深度、资金费率、真实滑点和网络延迟。

### 7. 运行模式

#### 模拟盘

使用实时公开行情，但只在本地数据库记录模拟订单，不向交易所发送订单。建议所有新策略先使用此模式。

#### 交易所测试网

使用交易所测试网 API 和测试资产发送市价单。策略必须绑定测试网账户。

#### 实盘

向真实交易所账户发送市价单。实盘必须同时满足：

- 策略绑定实盘账户。
- 账户通过连接测试。
- 服务器设置 `ALLOW_LIVE_TRADING=true`。
- 策略由管理员主动启动。

### 8. 资金分配与再平衡

每个策略可以设置组合资金占比，避免所有策略同时使用全部资金。

#### 只在开始时按比例分配

总资金为 10,000，策略占比为 20% 时，初始分配 2,000。后续盈亏留在该策略内，不再恢复到 20%。

适合：

- 希望不同策略独立记账
- 不想频繁转移资金
- 愿意接受长期比例漂移

#### 每次开仓前动态校准比例

程序会在下一次准备开仓前，根据组合最新权益计算目标资金。只有偏离超过容忍区间才会调整资金。

例如组合权益为 12,000，目标比例为 20%，目标资金就是 2,400。如果策略当前资金为 2,600，且偏离超过设置的容忍区间，程序会收回多余部分。

平台不会每秒强制再平衡，因为这会产生大量手续费和滑点。动态校准只在新开仓前触发，并且目前只支持模拟盘。

资金转入和收回会单独记录，不会被错误计算为策略利润。

### 9. 风险控制

每个策略可以设置：

- 每次最多投入
- 策略资金比例
- 止损百分比
- 止盈百分比
- 手续费估计
- 再平衡偏离容忍区间

单笔投入不能超过分配给策略的资金。策略当前只允许单向现货持仓，不会自动使用杠杆或做空。

### 10. 后台执行引擎

策略启动后，后台任务会：

1. 按设置的间隔读取 K 线。
2. 计算当前买入、卖出或观望信号。
3. 检查止损和止盈。
4. 检查策略资金上限。
5. 在动态模式下检查资金比例偏离。
6. 创建模拟订单或交易所订单。
7. 保存信号、错误和运行时间。

单个策略失败不会让整个服务退出。错误会显示在策略卡片中，下一轮仍会继续尝试。

### 11. 订单记录

订单页面保存：

- 订单时间
- 策略名称
- 模式
- 交易对
- 买入或卖出
- 数量
- 价格
- 触发原因，如规则、止损、止盈或再平衡

### 12. 数据与安全

默认使用 SQLite 数据库：

```text
data/trader.db
```

交易所凭据使用 `TRADING_MASTER_KEY` 派生的密钥加密。管理接口使用 Bearer Token 验证。

`TRADING_MASTER_KEY` 一旦用于保存账户，不能随意更换，否则已有密文将无法解密。

## 安装与启动

需要 Python 3.12 和 [uv](https://docs.astral.sh/uv/)。

```bash
uv sync --frozen
ADMIN_TOKEN='请替换为足够长的随机值' \
TRADING_MASTER_KEY='请使用另一段足够长的随机值' \
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

打开：

```text
http://localhost:8000
```

输入 `ADMIN_TOKEN` 登录。本地未配置环境变量时，开发令牌为 `local-dev-token`。对外部署前必须替换默认令牌。

### 环境变量

| 名称 | 默认值 | 用途 |
| --- | --- | --- |
| `ADMIN_TOKEN` | `local-dev-token` | Web 与 API 管理认证 |
| `TRADING_MASTER_KEY` | 回退到 `ADMIN_TOKEN` | 加密交易所凭据 |
| `DATABASE_URL` | `sqlite:///./data/trader.db` | SQLAlchemy 数据库地址 |
| `ALLOW_LIVE_TRADING` | `false` | 是否允许启动实盘策略 |

运行测试：

```bash
uv run pytest
```


## 当前限制

当前版本是单管理员、单服务实例的现货量化 MVP，主要用于策略学习、回测、模拟和小规模测试。

尚未包含：

- 多用户与细粒度权限
- 双因素认证
- 做空、杠杆、期货和期权
- 限价单与复杂订单类型
- 订单簿级回测和真实滑点模型
- 多资产统一实时估值
- 实盘动态比例再平衡
- PostgreSQL 正式迁移管理
- 分布式任务锁、告警和高可用部署
- 交易所订单状态持续对账与灾难恢复

回测和模拟结果只能说明策略过去或当前的表现，不能保证未来收益。
